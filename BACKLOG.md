- **The scenario-switch round trip is the exit-condition test for whichever epic ports the SECOND scenario.** Phase 6 built the pause menu and the switch machinery, and proved the mechanics: converge, save, destroy the cluster, restore, resume. What it could not prove is the thing the machinery is ultimately for, because only scenario 03 is ported and there is nowhere to switch to. The test is: drill 03, switch to 06, drill 06, switch back to 03, and find 03 exactly where you left it - same tasks passed, same working tree, same commit. It is recorded here, in `WO-20260819-7840`'s notes, in `CONTEXT_STATE.md` and in the plan's self-review, in four places on purpose, because `AC-H3` of Phase 4 nearly lapsed by being written down only once.
- **A cost guard that does not depend on the drill working, or on the laptop being awake.** Idle teardown covers exactly one failure: you walked away from a *working* drill with your watcher running. It deliberately refuses to act when `lastActivityAt` is missing or stale, because destroying on information you do not have is worse - which means the cases it cannot cover are: `make up` with `make scenario` never run (no watcher exists at all, since `make up` is a bare terraform apply); a pod stuck in `ImagePullBackOff` so the stamp never appears; a pod that dies mid-drill so the stamp freezes; and a closed laptop, since the watcher is a laptop process. Every one of those bills indefinitely, and they are collectively the *more* expensive failure - the drill working and being abandoned is the case where you at least remember it exists. Wanted: something in a different failure domain from all of our code. An AWS Budgets alert is the cheapest and does not depend on anything of ours running; a scheduled max-lifetime teardown is the stronger version. Not the same mechanism as the idle clock and should not be bolted onto it.
- **The drill learner must not run on the owner's AWS credentials.** Today `scripts/config.toml` names one profile and everything - `make up`, the drill, the teardown - runs as it. That is right for the person who owns the account and wrong for anyone being handed the playground: the drill terminal is `cluster-admin`, so whatever the profile can do, the learner can do. The shape wanted is a scoped identity that can do what the scenarios call for and nothing else - no oversized EC2, no touching the node group's scaling or its AMI, no IAM, no leaving the practice VPC - so a curious or careless learner cannot run up a bill or brick the cluster out from under the drill. Note this is a different axis from `drill_allowed_cidrs`, which controls **who reaches** the GUI; this is **what they can do** once they are in. Not blocking: the owner is currently the only user.

- Explorer context menu, the way Cursor and VS Code have one: right-click a file for Copy Path, Copy Relative Path, Reveal, Rename, Delete, and Open in Integrated Terminal.
  The path copy is the one that earns its keep - you grab a path out of the tree so you can `cd` there and run something against it, and today a right-click in the explorer gets you the _browser's_ menu instead of ours, which is worse than having no menu at all.
  "Open in Integrated Terminal" is the interesting one here, because our terminal is a real tmux shell in the pod: it would `cd` the running session rather than spawning anything.
  Wants `preventDefault` on `contextmenu`, a small positioned menu component, and `navigator.clipboard.writeText` - which needs a secure context, so it works on the ALB over HTTPS and needs a `document.execCommand` fallback on plain http during local preview.
- Reload an open editor buffer when the file changes underneath it.
  The terminal is a real shell in the same working tree, so `git checkout`, `git revert` or a stray `>` redirect all change files the editor already has open, and Monaco keeps showing the stale copy until you close and reopen the tab.
  VS Code watches and reloads (or marks the buffer conflicted when it is dirty), and the same is wanted here - scenario 03 task 5 is `git revert && git push`, which is exactly a case where the file changes from the terminal while the editor has it open.
