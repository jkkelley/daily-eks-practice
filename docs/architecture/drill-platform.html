Startup order and handover

EKS cluster ──▶ cluster git ──▶ Argo CD ──▶ practice-app
                (GUI starts independently and reports what it waits on)

The Makefile is demoted, never archived - if the GUI is the only way in and it breaks, there is no way in. make up/down/kubeconfig stay on the laptop forever; you cannot create a cluster from a pod that does not exist, nor destroy the floor you stand on. Everything else moves into the GUI, and those targets refuse while the GUI holds the wheel - explaining what they would break, with FORCE=1 as the escape hatch.

Decisions

Q1Argo CD reads exactly one source, forever

Cluster git is permanent platform infra built at make up. One Application, always. GitHub becomes its upstream, so scenarios 09 and 12 keep a real push/pull loop.

Rejected: swapping two Applications per drill, retiring the GitHub Application, a separate namespace. All three manage a conflict that need not exist.

Q2Progress is a save file, not a diary

Curriculum progress is a git bundle in drill-progress/ on your laptop, gitignored. Live session state is a ConfigMap. Resume converges to a declared state rather than replaying actions.

Rejected: a DrillProgress CRD, etcd snapshots (unavailable on EKS), Velero, pushing drill branches to GitHub, a database.

Q2aA watcher syncs on every task pass

Kubernetes watch API, not polling. The bundle is streamed out with kubectl exec ... git bundle create -, so no port-forward is held open. Atomic temp-file writes. Lifecycle is part of the session apply.

Q3Internet-facing ALB, three conditions

~$1 per 30-hour cycle. Shared IngressGroup so everything future joins one ALB. A pre-destroy hook, because the controller owns the ALB and Terraform cannot sequence its deletion. Source-IP restricted SG, without which this is an unauthenticated cluster-admin web terminal on the public internet.

Deferred: ALB OIDC auth - needs HTTPS → ACM → a Route53 domain not currently configured. It is the multi-user growth path.

Q4Integrations are contextual, and mostly not iframes

Native widgets from the Argo and Prometheus APIs are preferred - they look like this app. Grafana d-solo for single charts. Reverse proxy for full apps when the lesson is the app.

Why one host, path-routed: subdomain-per-app cannot be wrapped - different origins block framing and cookies.

Q5One long-lived pod; sessions are append-only

make scenario N=NN switches what the mothership is doing, it does not build a new pod. Redoing a scenario creates a new session in a results table with running totals. Nothing is overwritten.

Q6TypeScript both ends

Fastify + node-pty + @kubernetes/client-node behind React + Vite + xterm.js + Monaco. Shared websocket message types make protocol mismatches compile errors.

Rejected: hand-rolling RFC6455 - only ever justified by the stdlib-only constraint, which died when we chose to build an image.

Q7Refuse and explain, with an escape hatch

Locked targets name the consequence, not just the refusal. FORCE=1 overrides, so a stale lock never forces you to destroy a cluster mid-drill. GUI on 8090, clear of argo-ui (8080) and grafana-ui (3000).

Known unknown

The Argo-clones-cluster-git spike is unproven

The entire GitOps half of this design rests on Argo CD successfully cloning from the in-cluster git server over the chosen protocol. Git supports it and Argo shells out to git, but this is assumed rather than demonstrated. It belongs at the front of the implementation plan. Fallback if it fails is a proper HTTP git backend in the pod - more moving parts, not a redesign.
